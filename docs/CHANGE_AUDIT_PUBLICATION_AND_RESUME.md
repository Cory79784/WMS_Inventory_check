# PC 发布、PDA 执行与进度恢复

## 使用

1. Cloudflare Dashboard → Workers & Pages → `wms-inventory-check` → Settings → Variables and Secrets，新建 **Secret** `CHANGE_AUDIT_MANAGEMENT_KEY`。值为至少 24 位随机字符（建议 32 位以上），不要复用业务账号密码，不要提交到 Git。
2. 本 PR 不部署；验收部署时使 Secret 对新版本生效。原有公开库位核查不需要登录。
3. PC 打开「库存变动核查」→「任务管理（PC）」填写该密钥，授权此电脑。授权 Cookie 为 HttpOnly、Secure、SameSite=Strict，仅限新功能 API 路径，有效期 30 天；关闭浏览器仍保留。取消本机授权清除此 Cookie，轮换 Secret 使全部旧授权失效。
4. PC 选快照并配置路线，创建任务。新任务和升级前的旧任务都是 **草稿**，不会自动下发 PDA。检查冻结路线后点击「发布给 PDA」。路线配置要变更时，从比较面板配置并建立一个新草稿，再撤回旧任务、发布新任务；没有就地改写已发布计划的接口。
5. PDA/手机现在显示「库存变动核查」，仅列出当前厅的已发布任务，只提供执行页面；不加载快照管理、不显示任务创建/发布/撤回/删除/导出、文件导入导出入口。原库位核查、条码检索等功能保持。
6. PC 可撤回或删除任务。删除为软删除，保留结果和照片。PC 勾选「包含已删除历史任务（只读导出）」可查看并按 taskId 导出已保存结果。删除不可复活；需要新任务则重新创建。

## 边界

- **权限由管理凭证决定，不能由 User-Agent、屏幕宽度或“这是一台 PC”决定。** 未授权的 PC 也只是公开执行端；持有管理密钥的人拥有管理能力，不可能技术上阻止其在其他设备手动调用管理 API。因此密钥只授权可信 PC，不分发给 PDA。
- 没有密钥或少于 24 位时管理权限默认关闭。密钥只 POST 给同源管理会话接口，不写入 localStorage、源码或 URL；后端用 HMAC Cookie 验证后续请求，支持服务器自动化使用同一密钥请求头。
- 这是新增库存变动任务的管理权限，不是为原有公开网站恢复全站登录，也没有改变既有公共库存查询、原核查或原导入导出 API 的权限模型。
- 库厅是数据分区而非人员权限：执行者可以选择 H1/H2/H3，API 始终验证 hallId 与 taskId 的归属。任务结果不写入原核查表，也不覆盖其他任务、WMS 快照。
- 已发布任务执行仍公开可访问，符合原先取消全站登录的要求。

## 发布生命周期与竞争保护

增量表 `change_audit_publications(task_id,status,revision,updated_at)`；迁移 `0007_change_audit_publications.sql`，并进入现有幂等初始化。无删除、重建旧表或 R2 文件。状态 DRAFT / PUBLISHED / WITHDRAWN / DELETED；每次发布、撤回、删除递增 publication revision。

普通请求只能读取 PUBLISHED。创建、生命周期变更、任务导出和历史查看要求管理授权。结果保存、照片上传除了原结果 revision 与当前 WMS 指针校验，还要求请求中的 publication revision 等于服务端。最终结果 INSERT/UPDATE 和照片关联 INSERT 在同一 SQL 中再次检查发布状态和 revision，防止撤回/删除与保存并发时写穿。已撤回或删除的管理端也不能继续写。

页面进入、切回、窗口返回会检查状态；功能前台打开时每 30 秒发出一次任务列表请求，有当前任务再发出一次状态请求。状态只读取元数据和聚合结果/照片计数，不取库存、计划 JSON 或重算路线。结果计数变化时单独读取该 taskId 的结果/照片，复用冻结计划。无变化不请求详细结果。离线/后台没有“立即得知删除”的保证：后端写权限立即收回，界面在恢复联网或下一次状态检查（正常前台约 30 秒）时移除任务。

并发设备的进度以服务器结果为准，位置选择按设备保存。远端 revision 与本机待同步草稿冲突时阻止覆盖，不把本机未成功保存的数据计为已保存。

## 刷新、关闭与恢复

- `localStorage` 保存当前库厅、每厅选项卡、每厅选中任务、每任务当前位置、原核查每厅最近库位。刷新和关闭/重新打开都恢复；这取代了之前“新会话默认 H1”的规则。PDA 恢复到原导入/导出页时回到允许的核查页。
- 任务选择恢复先验证服务器，撤回/删除任务不恢复可编辑页面。正常已保存进度来自服务器，本地位置不会覆盖另一台设备的当前位置。
- 任务数量/备注等编辑立即写本地草稿，650ms 防抖写服务器；照片原文件存入 IndexedDB，保留稳定上传 ID。草稿带 publication revision，包括照片，旧发布修订的离线内容不会绑定到新修订。
- 原库位核查也保留独立的 `hall:location:referenceImportId` 文本草稿及原照片 File（IndexedDB 单独命名空间）。恢复时比较已知服务器基线，发生变动则保留草稿并阻止自动覆盖。原结果接口和核查判定不变。
- 页内跳转、换厅、换选项卡、visibilitychange/pagehide/beforeunload 尝试立即同步。不会为“保存进度”隐式把未检查的数量确认为正常。
- 浏览器不能保证退出时异步 fetch/IndexedDB 完成。因此可靠性依赖平时保存，退出时的请求只是补充；未同步时使用原生离开确认（文案由浏览器决定），存储失败有页面告警。系统强制杀进程、清站点数据/隐私窗口/磁盘故障不能承诺保留未同步内容。
- 无效任务的草稿留在原任务命名空间，不转发其他任务。用户可明确选择「保留旧草稿副本并重新打开有效任务」：先创建本机隔离副本（包括待上传照片），再清除活动队列，服务器仅加载新有效发布版本；隔离副本不自动恢复或上传。该副本用于保留现场证据，当前不提供自动合并；有本机存储错误时不得退出。
