# WMS 快照对比

## 数据库确认

以下结论来自数据库建表、导入发布和核查保存代码；未连接生产 D1，不据此声称线上实际保存了多少版本。

- `inventory_imports` 保存版本号、库厅、文件名、文件摘要、导入/源导出时间、发布状态等元数据。
- `inventory_stock_rows` 按 import_id 保存解析后的库位、SKU、条码、商品名称、账面数量、可用/分配/冻结数量等库存行。发布新版本切换 `active_hall_imports`，不会覆盖旧版库存行。
- `location_inspections`、`sku_inspections` 保存绑定参考版本的实盘结果；相同版本重复保存更新当前结果，并非每次编辑都有一份完整历史副本。
- 照片文件保存在 R2，数据库记录照片及其明细关联。原始 WMS Excel 文件本体没有作为版本文件保存。

## 使用

电脑端标题栏“库存变动核查”菜单中提供默认折叠的“WMS 快照对比”（已从“导出”页迁移）。展开后选择同库厅的旧、新已发布/历史版本，点击“查看变动库位”。默认选版本号最高的两版；当前生效版本另有标注。至少需要两个已保留版本。

每个变动库位可折叠展开，显示 SKU 新增、移除、数量变化及新减旧的数值。库位标记区分新增有货、清空、其他变化。库位总量包括未变化的 SKU，变动清单只含数量变化的 SKU。按库位/SKU 搜索，预览每页 20 库位。

“导出全部快照变动”导出整个对比结果，不受预览搜索和分页影响。语言使用上方中文/英语/德语选择，固定标签本地翻译，商品名称、编码保持原文，无外部翻译 API。附带版本 ID、原文件名和时间元数据。

新版恰为当前生效版本时可创建独立核查任务；不写入原库位核查结果，不更改生效版本。任务保存、蛇形路线及风险说明见 `INVENTORY_CHANGE_AUDIT.md`。后续发布新版本后旧任务只读。

PDA/手机端仍遵循现有隐藏导入导出入口规则，不添加文件操作入口。

## 比较边界与资源

比较键为规范化库位（去首尾空格、大写）+ SKU（去首尾空格、保留大小写），同键重复库存行先汇总 system_qty。只比较账面总数量，不比较商品名称、条码、冻结/可用量或实盘备注照片。零数量行视为无库存；SKU 转移库位表现为原位置移除、目标位置新增，不能推断实际搬运原因。

`GET /api/inventory/snapshot-versions` 列出指定库厅 PUBLISHED/ARCHIVED 版本；`GET /api/inventory/snapshot-compare` 接收 hallId、oldImportId、newImportId，要求两版同库厅、旧版号小于新版号。禁止 STAGING/FAILED 及跨库厅版本。

无需新增表、迁移、重导文件或复制库存。展开时读取版本列表，主动比较时执行只读汇总查询，客户端搜索/分页和导出复用该次结果，不轮询。比较仍会消耗 D1 读取与 Worker 计算资源，取决于两版库存规模；浏览器只渲染当前页，但会接收完整变动结果。未做生产规模压测。

## 验证

真实本地 D1（Miniflare）测试覆盖重复行、库存不变、移位、清空、新增、零行、完整库位总量、版本选择隔离、禁止写请求及数据库/生效指针不变。实际 XLSX 写出回读验证三种语言、前导零编码、原文商品名与数值。组件测试覆盖按需加载、折叠预览、完整导出、失效结果清理与历史版本核查入口限制。
