# 差异导出与照片关联修复（仅需求四、五、六）

## 范围

- 只修差异筛选、照片明细关联和 Excel 图片布局。
- 不增加英语/德语 Excel 导出，不改核查时间显示，不增加库存版本对比。
- main 代码备份分支：`backup/main-before-export-photo-fix-20261016`。
- 开发分支：`fix/export-photo-associations-phase1`。未合并、不部署。

## 差异定义与版本范围

已完成记录中，多货、少货、异常 SKU、人工备注、关联照片、退货勾选或退货码任一成立即纳入。
自动“盘点正常相符”提示与库位待复核状态本身不纳入无关正常 SKU。
SKU 备注/照片只作用于其明细；库位级备注/照片作为独立“库位存证”行出现一次，数量栏留空。
差异明细没有照片时仍然导出，照片栏为空。

导出默认保留“所有已保存版本（含历史）”，可显式选择“仅当前 WMS 版本”。选择范围只影响导出，不改写快照或核查数据。核查中记录仍不进入导出。

## 明细关联与兼容

每条明细使用稳定 lineId，同名 SKU、额外多货以及多条无 SKU 多货都各有 ID。保存时按 ID 更新，不能按 SKU 文字找第一行。
`inspection_photo_lines` 是新增的可重复创建的关联表，在明细尚未填写实盘数量时保存照片目标。
启动初始化自动创建此表；迁移 `0005_photo_line_links.sql` 也可在常规迁移流程中创建同一表。
已有库存、照片原图和历史快照不删除。已有明确指向明细的照片继续采用其原关联，无法证明归属的旧照片单独列为库位存证，不猜测 SKU。

前端照片目标下拉框显示明细编号，区分同名条目。已上传照片旁也可重新选择目标，修改后走现有自动保存。旧系统已经误绑定且无法确定真实目标的照片，需要人工选择正确明细，程序不能可靠还原拍摄意图。
原有无 SKU 多货必须拍照规则不变，有 SKU 多货/少货不强制增加照片。

## Excel 图片

先在 API 筛选最终明细，再按最终输出行号放图。每行多图横向排列，图片两个锚点均限制在该行、该照片单元格内，采用随单元格移动和调整大小的 twoCell 锚点。
行高 90 pt，图片显示上限 160×110 px，留出内边距；不改变原图二进制。同一对象只写入一份媒体资源，避免重复存储。

自动测试验证实际 XLSX 解包和回读后的图片行列、锚点、尺寸边界、原图字节和媒体去重。真实 Excel 的筛选/排序表现因客户端而异，仍需人工验收，不能仅凭自动测试宣称已在 Excel 中实际操作。

## 人工验收

1. 同库位建立正常 A、A 的额外多货、无 SKU 多货 1、无 SKU 多货 2、无照片少货 B。
2. 给 A 的多货拍一张，给无 SKU 1 拍两张、无 SKU 2 拍一张。确认自动保存后刷新。
3. 检查每张照片的明细编号正确，正常 A 和 B 没有借用其他行照片。
4. 导出仅差异：不出现正常 A；A 多货、两条无 SKU 和少货 B 均出现；B 图片为空；无 SKU 1 两图横排。
5. 库位另加整体备注或整体照片，确认只新增一条库位存证，不复制到每个 SKU。
6. 修改数量、重排/重载后再次保存，确认照片不串行且关联 ID 稳定。
7. 在 Excel 中筛选与取消筛选，多次检查图片不叠到相邻行。此项需要使用真实 Excel。
8. 分别选择当前版本、所有历史版本，核对输出范围，历史快照数量不改变。
9. PDA 验证拍照、扫码、软键盘、自动保存不退化；导入导出入口仍仅电脑端可见。
