# 库存变动核查（PC 首期）

## 使用与隔离

标题栏新增“库存变动核查”。原“导出”页只保留原实盘结果导出，原 WMS 比较组件和比较 API 被复用并迁移到新入口，历史比较及中文/英语/德语差异 Excel 导出保留。手机/PDA 不显示新入口，不提供文件导入导出；本次没有改动原库位核查页面、扫码逻辑或核查保存 API。

选择同库厅旧、新两个已保留版本，默认当前生效版本及其上一版。比较后，设置起点和配对，建立独立任务。新版必须仍是当前生效版本。历史比较可浏览、导出，不能启动当前实盘任务。任务列表显示最近 100 个；本浏览器之前选中的任务即使超过该列表也会恢复。

主要库位分类只有：库存变动、新增有货库位、变成空库位。按整个库位而非某一 SKU 是否清零判断。界面不突出增加/减少统计，数量对比折叠到次级信息。核查卡片显示新版全部 SKU（含未变 SKU），另保留已消失 SKU 的零账面核查行，方便登记遗留货物。可添加额外货物、数量、备注和照片；照片可关联稳定明细 ID 或库位整体。

所有明细通过正常、少货、额外货物等明确按钮操作完成且数量有效后，自动记为完成数量核查。账面清空且实盘全部为零还须人工勾选空位确认。发现残留时填真实数量，不要求勾选空位。填写/浏览/跳转/路过目视都不会自动填数量或确认正常。失败、等待保存的完成操作不计入服务器已完成进度。

## 数据库确认和增量

根据现有建表及导入代码确认：`inventory_imports` 与 `inventory_stock_rows` 保存版本元数据与解析库存，含客户编码和中英文商品名；新版本发布切换生效指针，不覆盖旧版。原 Excel 文件本体没有版本文件存储；没有托盘字段，不能推定整托。原实盘结果绑定参考版本，同版本更新不等于逐次编辑完整快照。本次未连接生产 D1，不声称生产实际版本数。

新增迁移 `0006_change_audit.sql`，启动初始化注册同一组可重复执行的建表语句：

| 新表 | 内容 |
| --- | --- |
| change_audit_tasks | 库厅、新旧 import ID、冻结的比较/路线/风险/目标计划、创建时间 |
| change_audit_results | 任务+库位唯一，独立数量/备注/空位确认/完成标志、修订号、保存时间 |
| change_audit_photos | 独立图片 ID、任务、库位、稳定明细 ID、R2 对象键 |

R2 前缀为 `change-audit/{hall}/{taskId}/{photoId}`。不写入原 `location_inspections`、`sku_inspections`、`inspection_photos`、照片关联表，也不修改库存快照。无需新密钥或新 Cloudflare 绑定，复用现有 D1/R2。此 PR 不执行生产迁移，不部署。

## 蛇形路线

默认奇数货架与下一偶数货架配对，按库位数字交替核查两侧，下一通道反向。末端不硬编码，不需要为没有目标的库位创建结果。即使某中间通道无目标，方向奇偶仍按通道计算。可设置起始货架、大小号端和无重复的例外配对；被例外占用的货架不会又进入默认配对。中途开始时，前段目标放到最后，界面提示补查，避免遗漏。

只将规范 `XXX-XXX-1` 位置加入步行路线，特殊编码和其他层单列，可手动打开核查。目标去重且全部保留，风险不参与排序。默认下一站从当前位置往后找未完成步行目标，到末端后检查之前遗漏的目标；特殊位置从清单打开。未知扫码位置只提示顺路目视不计数量核查，不把它加入任务或写成正常结果。

## 本地可解释风险规则

读取新版完整库存，按规范化库位+SKU 汇总，与原比较一致。客户编码冲突时不作该 SKU 的同客户风险断言。

- 多 SKU：新版整个库位的不同 SKU 数量，不只计变动明细。
- 同客户相近编码：客户+编码前半段建立索引，在代表候选内比较长公共前缀或少量尾部差异；编码过短不判断。
- 规格变体：识别明确颜色、尺寸、左右件、分箱后缀，或同客户商品名称中明确颜色/尺寸属性去除后的相同名称。只作疑似提示，保留 SKU 证据。
- 相邻/对面：当前通道两侧同号与前后一个位置的完整新版库存中，查找相近编码。
- 疑似移库：同 SKU 在变动清单存在反向变动，显示候选位置和数量，不强行一一配对，也不推断搬运原因。

不调用 AI/外部 API，不按数量大小或纯数字编码单独赋高风险，不假设托盘。风险不是错误概率。为控制开销，同客户前缀/规格桶最多保留 32 个不同 SKU 代表，每类每个库位显示一条代表线索，并非穷尽所有相似组合；不执行全库无约束两两比较。

## 请求与保存

- 页面首次进入读取版本元数据和最近任务列表；恢复选中任务时一次加载计划、结果和照片元数据。
- 历史比较主动请求一次。创建任务复用原比较逻辑并只读新版库存，计划计算/保存一次，正常创建响应直接携带计划，无需额外重载和刷新列表。
- 切换库位、搜索、翻页、折叠路线：零后端调用，不重算路线。
- 数量/备注编辑防抖 650ms 自动保存，同库位写入串行；不同库位独立保存。原样保留自动保存，也可用“保存本库位核查”立即保存。
- 保存带修订号。原子 SQL 同时检查修订号及当前生效版本；并发冲突保留草稿，不盲目覆盖。丢失响应重试相同内容可幂等确认。
- 照片单独上传和保存，立即展示本地预览，失败保留原 File 和重试 ID；额外明细先保存，防止照片绑定到不存在的行。
- 数量/备注草稿本地存储；待上传照片尝试保存在 IndexedDB，刷新后可重试。浏览器存储不可用会提示，需保留原文件并确认服务器保存成功。
- 同标签页刷新恢复菜单、任务和所选库位。未保存内容不会因清单跳转或菜单切换丢失。
- 无定时轮询。返回本菜单时检查一次生效指针；窗口重新获得焦点/可见时最多每 60 秒检查一次；加载和每次写入均检查版本。新版本发布后旧任务只读，既有结果、草稿保留，不自动替换基准。

计划 JSON 超过 1.8 MB 会明确拒绝创建，避免越过 D1 单行限制，不静默截断；非常大的任务需要后续分块存储设计。图片支持 JPG/PNG/WebP，每张不超过 10 MB。

## 验证与人工验收

自动测试覆盖路线方向、两侧交替、无目标中间通道、例外配对、特殊位置、目标完整性、风险不改变顺序、完整库存风险、三种分类、独立任务/结果/原图、空位确认、乐观锁、幂等重试、过期阻写、草稿恢复、快速编辑、照片失败重试、数量完成状态及 PC/PDA 入口。

上传样例仅本地只读解析：2,119 条数据均属于 H3。用这些完整新版行和人工构造的变动目标做覆盖检查，1,753 个库位分成 1,734 个标准一层与 19 个特殊位置，目标无遗漏、无重复。该检查不是实际历史变动结论，没有导入任何生产数据。Node 本地风险/路线计算约 29 ms，不能据此承诺生产 Worker 或大型仓库性能。

合并后部署前，建议在 PC 实际验收：选两版、设置配对、创建任务、逐项填数、空位残留、额外 SKU、照片关联、网络失败后重试、刷新恢复、多窗口冲突、新版发布后只读。实际仓库端部是否可通行、例外配对是否准确需现场确认。本次无真实 PDA 弹键盘或真实 Cloudflare 生产环境验证。

## 后续调整：共享原核查 UI 与独立任务导出

操作卡片及少货/多货弹窗从原页面提取到 `InspectionSkuCard`、`InspectionShortageModal`、`InspectionSurplusModal`。原页面继续使用默认参数、原状态与原回调，不改变原数量输入、保存时机或数据接口。任务通过单独适配器使用同一组件，开启按钮数量调整和账面数量强调，不提供实盘数字输入表单。

任务中“正常”确认参考账面数，“少货”用按钮选择少货件数并确认，“现场多货”沿用 SKU/条码/无 SKU 模式、退货字段、照片和备注。无 SKU 多货必须有对应明细照片后才能完成，服务端同样校验。所有必填计数完成后，按钮操作自动更新完成状态并保存，不再额外要求点击一套任务专用的数量确认按钮。单纯浏览或编辑备注不补填数量。旧版已消失货物以零账面数放在残留检查折叠区，空位确认可明确完成这些零数检查。

新版账面数以“系统数量”突出；过期任务显示“任务参考数量”，保持只读。新创建任务冻结可用/分配/冻结数，旧任务未保存这些字段时显示破折号，不能冒充为零。原 WMS 历史比较仍使用原快照数据，不写回。

任务“一键全相符”遇到已有记录先明确确认，移除额外行并清除任务当前备注、退货和照片关联。照片对象/独立照片元数据不物理删除，结果 JSON 中 `ignoredPhotoIds` 表示当前不再关联的证据。照片下拉调整通过结果 JSON 的 `photoLines` 覆盖原上传归属，受原任务修订号、库位归属和生效版本保护；不会修改原核查的照片表。以上均为可选 JSON 字段，不增加表、不需要新的数据库迁移，旧任务兼容。

每个任务提供折叠“本任务核查结果导出”，日期、库厅、旧/新版本和任务 ID 明确显示。文件名含完整 taskId；日期按浏览器本地显示，不硬编码某一天。`GET /api/inventory/change-audit/export?hallId=...&taskId=...&mode=all|differences` 只读取该任务的独立结果和照片，不能按日期/库厅/版本合并任务。仅导出服务器已完成结果，并显示未完成数量。正常任务有未保存更改时等待保存后导出；过期任务可直接导出服务器历史结果，但明确不含本地草稿。

任务差异包括数量差、额外/无 SKU 货物、人工备注、对应明细照片、退货标记/码。自动“盘点正常相符”不会使正常行成为差异。库位备注/整体照片只生成一条库位存证行，不扩散到其他 SKU。旧版快照变动表和现场任务结果使用不同名称和入口。

任务和原核查分别查询、分别适配，Excel 复用原 `buildInspectionWorkbook` 的列顺序、颜色、90pt 照片行高、同一明细多图排列及双角点同一行的锚点、原图去重。独立元数据页标明任务 ID、创建时间、参考版本、完成/未完成数量。中/英/德标签为本地字典，原商品名称/人工备注/编码不翻译。JPEG/PNG 原图不转换；任务 WebP 照片导出时在浏览器转 PNG 嵌入 Excel，R2 原文件保持不变，原核查导出行为不变。

追加验证覆盖同一天同版本的任务 A/B 与原核查结果分离，未完成排除，过期任务导出，明细/库位证据隔离，退货、无 SKU 照片校验，图片归属调整和全相符隐藏关联，三种语言真实 XLSX 回读及图片行列锚点。原页面交互回归继续通过。真实 PC 的图片解码、WebP 转换与 Excel 筛选排序仍需验收。
